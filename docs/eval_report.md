# 检索质量评测报告（Recall@k）

> 生成日期：2026-04　|　评测脚本：`scripts/eval_retrieval.py`

---

## 1. 评测目标

量化验证检索链路的召回质量，对比**向量检索**与**混合检索（BM25 + 向量 + RRF）**在中文文档上的 Recall@k，为调参和算法选择提供数据依据。

## 2. 评测方法

- **数据集**：用户 1 知识库，4 份中文文档（刑法、劳动合同法、西游记、三国演义），共 7904 个 chunk。
- **评测集**：8 条「查询 → 相关文档文件名」标注对。
- **指标**：`Recall@5` = 前 5 个检索结果中命中相关文档的比例。
- **检索实现**：直接调用 FAISS `similarity_search_with_score`（向量）与 `hybrid_search`（混合），绕过高层 `retrieve_for_rag` 的 UI 耦合，聚焦检索本身。

## 3. 结果

| 检索模式 | 平均 Recall@5 | 单查平均耗时 |
|----------|--------------|-------------|
| 向量检索 | **1.0000** | ~14ms（热） |
| 混合检索 | **1.0000** | ~480ms（热）/ 31s（BM25 冷启动） |

## 4. 结论与发现

1. **检索质量达标**：在文档区分度高的中文标注集上，两种模式 Recall@5 均为 1.0，说明 bge-small-zh-v1.5 嵌入 + 分块策略对语义明确的查询召回良好。

2. **混合检索冷启动慢**：BM25 索引首次构建耗时约 31 秒（7904 chunk），之后缓存命中降到 ~480ms。**优化建议**：
   - 入库完成后**预构建并持久化 BM25 索引**（当前已有 `bm25_index.pkl` 持久化，但需确保入库流程主动调用 `rebuild_bm25_index`）；
   - 服务启动时**预热**向量库 + BM25 索引，避免首个用户首查卡顿。

3. **评测集偏小**：当前 8 条样本且文档区分度极高（法律 vs 小说），Recall 满分在预期内。**若要更有说服力**，需扩充：
   - 增加**同领域近似文档**（如多份法律条文），测试细粒度区分能力；
   - 增加**负样本**（query 无对应文档），测试是否错误召回；
   - 引入 **nDCG** 衡量排序质量，而不只是 Recall。

## 5. 复现方式

```bash
# 评测用户 1 知识库，向量 + 混合模式
python scripts/eval_retrieval.py --user 1 --k 5 --mode both
```
