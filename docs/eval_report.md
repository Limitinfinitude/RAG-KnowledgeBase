# 检索质量评测报告（Recall@k / nDCG@k / MRR）

> 更新日期：2026-08-15　|　评测脚本：`scripts/eval_retrieval.py`

---

## 1. 评测目标

量化验证检索链路的召回质量与排序质量，对比**向量检索**与**混合检索（BM25 + 向量 + RRF）**，重点考察**同领域细粒度区分**能力（而非此前"法律 vs 小说"的粗粒度区分）。

## 2. 评测语料（真实图书章节）

采用开源书《AI Agent》（`E:\goodgithub\ai-agent-book`）第 1-5 章正文作为评测语料，入库到专门评测用户（user 98）：

| 文档 | 章节主题 | 大小 | chunk 数 |
|------|---------|------|---------|
| `chapter1_Agent入门_20260815.md` | Agent 基础（LLM+上下文+工具、ReAct、Harness 工程） | 73KB | 240 |
| `chapter2_上下文工程_20260815.md` | 上下文工程（KV Cache、提示工程、系统提示词） | 127KB | 351 |
| `chapter3_用户记忆与知识库_20260815.md` | 用户记忆与知识库（记忆层次、RAG、结构化索引） | 105KB | 361 |
| `chapter4_工具_20260815.md` | 工具（分类、MCP、事件驱动、Skill 披露） | 106KB | 330 |
| `chapter5_CodingAgent与通用Agent_20260815.md` | Coding Agent（代码执行、元能力） | 108KB | 333 |

> 共 **1615 个 chunk**。这 5 章主题同域（都是 AI Agent），且词汇大量重叠（"上下文""工具""记忆""代码"跨章出现），比此前的异域语料（法律 vs 小说 vs 编程）**更能考验细粒度区分**。

## 3. 评测集设计（22 条）

| 类型 | 数量 | 说明 |
|------|------|------|

## 4. 评测结果

| 指标 | 向量检索 | 混合检索 |
|------|---------|---------|
| Recall@5（全部 22 条） | 0.8409 | **0.8409** |
| nDCG@5 | 2.2391 | **2.3620** |
| MRR | 0.8409 | **0.8636** |

### 4.1 关键逐条观察

- **14 条各章独有 query 全部命中正确章节**（Recall=1.0）——在 1615 chunk 的同域语料中，系统能准确定位「KV Cache → 第2章」「MCP → 第4章」「RAPTOR/GraphRAG → 第3章」。
- **4 条词汇陷阱全部命中正确章节**——「上下文是眼睛」（第1章）与「上下文工程」（第2章）能正确区分，未被重叠词汇误导。
- **多相关样本**「如何防止 Agent 陷入无限循环」仅命中第1章、漏掉第2章（Recall=0.5）。**这说明单条 query 跨多文档时，纯 top-k 召回有天花板**——k 越小越明显。
- **混合检索排序质量优于向量**：nDCG 2.362 vs 2.239，MRR 0.864 vs 0.841——RRF 融合对排序有增益，与「混合检索改善排序」的设计预期一致。

## 5. 关键发现（真实问题）

### 5.1 负样本误召回（未修复，需阈值兜底）

3 条负样本（红烧肉/世界杯/房产过户）在两种模式下都**错误返回了章节文档**。

**根因**：`similarity_search_with_score(query, k=5)` 无条件返回 top-5 最近邻，**缺少低分阈值兜底**。`SIMILARITY_THRESHOLD`（0.3）过滤位于高层 `finalize_retrieval_from_scored`，直接向量检索路径未做该过滤。

**优化方向**：
1. 检索出口统一施加低分阈值，低于阈值返回「未找到相关内容」而非凑数；
2. 重新校准 distance→similarity 分数映射（`1/(1+L2)` 压缩了分数区间，正负样本区分度不足）。

### 5.2 多相关查询召回不完整

单条 query 对应多个文档时，固定 top-k 无法保证全部召回。可考虑**查询分解**（项目已有 `services/query_decompose.py`）或动态增大 k。
