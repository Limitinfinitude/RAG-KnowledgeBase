## 二、检索层结果（k=5，824 条）

| 模式 | Recall@5 | Recall@3 | nDCG@5 | MRR | 误召回率 | Balanced |
|------|----------|----------|--------|-----|----------|----------|
| 向量 | 0.9786 | 0.9786 | 0.9737 | 0.9721 | 64.10% | 0.525 |
| 混合（BM25+向量+RRF） | **0.9933** | 0.9920 | 0.9801 | 0.9755 | 71.79% | 0.439 |
| 重排（严格阈值口径） | 0.9859 | 0.9859 | 0.9846 | 0.9846 | **11.54%** | **0.933** |
| 生产全管线（含低分回退） | 0.9893 | 0.9893 | 0.9881 | 0.9877 | 73.08%* | — |

\* 生产口径的 73% 中 48 条为 LOW_QUALITY_FALLBACK 设计行为（无结果过阈值时保留 3 条低分文档，top1 分≈0），真过阈值泄漏与严格口径一致（9 条，11.5%）。**生产形态下检索层不硬拦负样本，防线交给 LLM 拒答层**——见端到端拒答指标。

分来源 Recall@5（重排模式）：CMRC 0.996 / DuReader 0.992 / 维基长文 1.000 / 自建旧 0.982 / 自建新 0.929（新自建查询最细粒度——表格/参数类查询如"刹车油更换周期"，是当前最弱项）。

与 0817 基线对比：重排 Balanced 0.991 → 0.933。原因不是退化，而是 **v2 负样本难度大幅提升**（陷阱 25 条 vs 6 条，且语料从 10 文档/110 块扩到 155 文档/4194 块、多主题混排文件）。正样本召回在语料扩大 38 倍后仅降 0.4 个点（0.992→0.989 生产口径），检索质量稳定。

## 三、阈值敏感性（重放，正 746/负 78）

| SIMILARITY_THRESHOLD | 正样本存活 | 负样本泄漏 | Balanced |
|---|---|---|---|
| 0.20 / 0.25 | 99.20% | 14.10% | 0.9207 |
| **0.30（现行）** | 98.93% | 12.82% | 0.9268 |
| 0.35 | 98.79% | 10.26% | 0.9405 |
| **0.40（建议）** | 98.26% | **5.13%** | **0.9653** |
| 0.50 | 97.99% | 5.13% | 0.9641 |

分数分布：正样本 max 分 p5=0.669 / p25=0.978；负样本 p75=0.103 / p95=0.816。**建议将 SIMILARITY_THRESHOLD 从 0.3 上调至 0.4**：泄漏减半（12.8%→5.1%），正样本损失仅 0.7 个点；剩余 4 条泄漏分值 ≥0.81，属重排模型本身被骗的硬陷阱（如"智能音箱能提醒给宠物犬打疫苗吗"），阈值无法解决，由 LLM 拒答层兜底。

## 四、端到端结果（80 正分层 + 20 陷阱负，生产管线 hybrid→重排→父块扩展→LLM）

| 指标 | 结果 | 与 0817 基线对比 |
|------|------|------------------|
| Faithfulness（主张支持率） | **0.995** | 0.992 → 持平略升 |
| Answer Relevancy | 0.931 | 0.958 → 略降（v2 查询含口语化搜索问句，难度更高） |
| Context Precision（资料有用度） | 0.927 | 0.958 → 略降（同上） |
| **Answer Correctness（对权威 GT 答案）** | **0.938**（n=47） | 新指标，0817 无 GT 不可比 |
| **Context Recall（GT 要点被上下文覆盖）** | **0.957**（n=47） | 新指标 |
| **拒答正确性（陷阱负）** | **0.980** | 0.983 → 持平 |
| 延迟 | 检索 p50 2163ms / p90 2959ms；生成 p50 1960ms / p90 4528ms | 新增观测 |

**关键验证——双层防线成立**：生产管线对 20 条陷阱负样本全部送入了上下文（多数为低分回退的 2-3 条文档），但 LLM 拒答层 18/20 满分 10、其余 9 分，0.980 正确拒答。即"检索层不硬拦 + 生成层拒绝编造"的设计在对抗性陷阱下依然有效。检索延迟 p50≈2.2s，其中云端重排往返占大头——是后续体验优化的首要候选（本地小模型重排或异步预取）。

## 六、结论与建议

1. **检索质量**：语料规模 ×38 后正样本召回 0.989（生产口径），跨五个来源稳定；混合检索对召回提升明显（+1.5pt）但无判别力，重排是唯一可靠负样本防线——与 0817 结论一致并进一步强化。
2. **立即可做**：`SIMILARITY_THRESHOLD 0.3 → 0.4`（一处 config 改动，泄漏减半）。
3. **弱项**：表格/参数类细粒度查询（自建新 0.929）——csv/xlsx 分块策略或表格序列化可再优化；硬陷阱泄漏靠 LLM 拒答层兜底（见 e2e）。
4. **评测资产沉淀**：824 条评测集+构建脚本可复现，后续任何检索侧改动跑一次 `--mode all` 即可回归对比。
